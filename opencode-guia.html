1 ¿Qué es opencode?

opencode es un agente de IA open-source para desarrollo que corre en tu terminal. Piensa en Claude Code pero:

  • Open-source — el código está en GitHub (anomalyco/opencode, ~195K estrellas).
  • Multi-proveedor — usa Claude, OpenAI, DeepSeek, cualquier modelo. No estás atado a un vendor.
  • Multi-agente — agentes especializados (build, plan, debug) y configuración por agente.
  • Plan gratis real — con opencode Go te regalan crédito para empezar.
  • Cualquier terminal — es un binario. Corres opencode y listo, sin IDE.

Es un agente agentic: lee tu código, usa tool calling (edita archivos, corre comandos, consulta el repo) y trabaja contigo en ciclos. No es un chatbot: es un ingeniero junior que no se cansa.

Dato: opencode usa un modelo central que puede delegar trabajo a agentes sub-agentes. Eso es exactamente lo que aprovechamos en la sección 3 para orquestar modelos.

2 Instalación y primeros pasos

Paso 1: instala

INSTALACIÓN
curl -fsSL https://opencode.ai/install | bash

También disponible vía npm (npm install -g opencode-ai), Homebrew (brew install anomalyco/tap/opencode) o binarios desde GitHub Releases.

Paso 2: conéctate a un proveedor

Dentro de opencode usa /connect para conectar proveedores (opencode, Anthropic, OpenAI, etc.) o configura tu API key en opencode.json:

CONFIG DE PROVIDERS
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": { "apiKey": "sk-ant-..." },
    "opencode-go": { "apiKey": "oc-go-..." }
  }
}

Paso 3: verifica

  • opencode --version — confirma que el binario quedó instalado.
  • opencode en la raíz de tu proyecto — arranca la TUI.
  • /init — opencode analiza tu repo y genera AGENTS.md (las reglas de trabajo para el agente).
  • Escribe tu primer prompt: "¿cómo está estructurado este proyecto?".

Pro tip: haz commit de tu AGENTS.md. Es el contexto permanente del agente: convenciones, arquitectura, comandos de build/lint/test. Un buen AGENTS.md vale más que cualquier modelo caro.

3 Modelos y orquestación — LA PARTE CENTRAL

Aquí está la idea que cambia tu flujo de trabajo. No necesitas un modelo para todo. Necesitas dos:

Recomendado

Agente orquestador

Un modelo fuerte que planea, razona y decide qué hacer. Es quien lee tu prompt, descompone el problema, decide el orden de las operaciones y usa tool calling. Costo alto, pero poquísimas llamadas: solo las decisiones.

anthropic/claude-opus-5 (o cualquier modelo top: GPT-5.6, Gemini 3 Pro…)

Recomendado

Modelo ejecutor

Un modelo rápido y barato que ejecuta: edita archivos, corre comandos, hace el trabajo mecánico. Se le llama muchísimo (cada paso de código), así que debe ser barato.

opencode-go/deepseek-v4-flash — rápido, barato, incluido en Go.

Skill lista para usar: Orchestrator Plan

Cuando el orquestador recibe una tarea grande, genera un plan.md con objetivo, contexto, tareas en orden y criterios de aceptación verificables — y el ejecutor lo sigue sin inventar arquitectura. Ya la empaqueté para ti:

Descargar skill orchestrator-plan.zip

Instálala en ~/.agents/skills/ o en .agents/skills/ de tu proyecto. También disponible en skills.html.

Cómo se combinan

El orquestador usa tool calling: no "piensa" cada línea, sino que delega tareas de ejecución al modelo rápido. Flujo real:

┌──────────────────────────────────────────────────────────────┐
│                    TU PROMPT                                  │
│         "Agrega login con JWT al endpoint /auth"              │
└──────────────────────────┬───────────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────────┐
│              AGENTE ORQUESTADOR  (fuerte, caro)               │
│        anthropic/claude-opus-5 · ~10 llamadas totales         │
│                                                              │
│  1. Lee el repo, entiende el stack                          │
│  2. Decide: "crear middleware → ruta /auth → tests"          │
│  3. Delega cada subtarea al ejecutor                         │
└──────────────────────────┬───────────────────────────────────┘
                           ▼
┌──────────────────────────────────────────────────────────────┐
│               MODELO EJECUTOR  (rápido, barato)               │
│       opencode-go/deepseek-v4-flash · ~200 llamadas           │
│                                                              │
│  · escribe auth.middleware.js                                │
│  · escribe la ruta /auth/login                               │
│  · corre los tests, corrige errores                          │
└──────────────────────────────────────────────────────────────┘

Plan con el fuerte, ejecuta con el rápido

La regla de oro: "plan con el fuerte, ejecuta con el rápido". El modelo caro toma decisiones en llamadas contadas; el barato hace las miles de ediciones mecánicas. Tu costo baja drásticamente y la velocidad de respuesta sube.

4 Comandos para cambiar de modelo

Todo dentro de la TUI, con la barra /:

Comando Qué hace
/models Abre el selector interactivo de modelos
/model Muestra el modelo actual del agente activo
/agents Lista los agentes disponibles (build, plan, debug, custom)
/init Genera/actualiza el AGENTS.md del proyecto
/help Todos los comandos disponibles
/connect Conecta y gestiona proveedores/API keys

Cambiar el modelo del agente activo

Cuando estás en un agente (p. ej. build), /models cambia el modelo de ese agente. Es decir: puedes tener cada agente con su modelo propio. Setup que yo uso:

MODELOS POR AGENTE
{
  "$schema": "https://opencode.ai/config.json",
  "model": "opencode-go/deepseek-v4-flash",
  "agents": {
    "orchestrator": { "model": "anthropic/claude-opus-4" },
    "executor": { "model": "opencode-go/deepseek-v4-flash" }
  }
}

Forzar modelo en el prompt

Escribe @model en tu mensaje para forzar el modelo de ese turno, sin tocar la configuración:

PROMPT
@model anthropic/claude-opus-5
Analiza esta arquitectura y dime qué refactor harías. No edites nada aún.

Perfecto para usar el orquestador solo cuando lo necesitas: planear con Opus, ejecutar con DeepSeek V4 Flash.

Plan mode: el hábito que te ahorra rehacer todo

Presiona Tab para alternar entre Build mode (edita archivos) y Plan mode (solo analiza y propone). Regla que me ahorra horas:

  • Features grandes → primero Plan mode, revisa el plan, y recién ahí cambia a Build.
  • Features chicas → directo a Build.
FLUJO RECOMENDADO
opencode                  # en la raíz del proyecto
/init                     # primera vez: genera AGENTS.md
@model opencode-go/deepseek-v4-flash   # ejecutor rápido por defecto
[TAB] → plan mode        # "agrega auth JWT a /auth: hazme un plan"
[TAB] → build mode       # "ok, ejecútalo"
/compact                  # si la conversación se alarga, compáctala

Buenas prácticas de prompt

  • Contexto por defecto: el @ para referenciar archivos: explica @src/api/index.ts.
  • Habla como a un junior: da contexto, ejemplos y criterios de éxito.
  • Específico > general: "refactoriza el handler en @routes/auth.js para usar async/await" funciona mejor que "arregla el código".
  • Itera: el agente hace, tú revisas el diff, corriges, repites.
